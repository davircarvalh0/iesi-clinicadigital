## Perguntas prováveis

| Pergunta | Resposta (com evidência) |
| --- | --- |
| E se o RabbitMQ cair entre gravar a consulta e publicar? | A outbox guarda o evento na mesma transação; o publicador tenta de novo e só marca como publicado com a confirmação do broker (BL-01/02, `test:us01:reinicio`, `test:us05`). |
| E se o mesmo evento chegar duas vezes? | O `id_evento` é registrado na mesma transação do efeito; a repetição só gera a atividade *evento duplicado* (ensaio, passo 3). |
| E se o WhatsApp não responder? | Se o pedido não saiu, há nova tentativa. Se pode ter saído, o lembrete fica *sem confirmação* e a recepção decide; reenviar sozinho poderia duplicar a mensagem ([US-15](US-15.md)). |
| Como garantem a LGPD? | Sem autorização registrada não há envio; atividades, logs, painel e trilha não guardam CPF nem telefone; só dados fictícios ([US-14](US-14.md), [US-16](US-16.md)). |
| Como sabem que tudo funciona junto? | `npm run verificar` sobe tudo do zero e roda 255 testes em cerca de 6 minutos; a CI repete isso a cada PR ([verificacao.md](evidencias/verificacao.md)). |
| Por que não chamar os serviços diretamente? | Acoplamento temporal: com eventos, a Notificação pode cair e se recuperar sem perder nada (demonstração 4). |
